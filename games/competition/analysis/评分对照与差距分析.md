# 评分对照与差距分析

## 一、结论

本项目符合“工业企业数智化转型综合解决方案”赛题，可选择官方列出的“设备智能运维与健康管理”方向。铁路基础设施属于典型工业装备与生产运营基础设施，当前系统已经形成视频采集、解帧、视觉语言描述、关键词抽取、PostgreSQL 入库和 Web 复核的真实闭环。

当前材料的主要问题不是方向不符，而是证据与文档结构没有完全围绕评分标准组织。按现有初稿保守估计约为 **65-72 分**。完成双语最小闭环、性能与价值量化、实施和投入产出章节后，材料才具备冲击 **85 分以上** 的基础。

| 官方要求 | 当前符合情况 | 已有内容或证据 | 主要缺口 |

## 四、必须纠正的表述风险

1. “双语风险识别”目前主要是架构预留。正式稿应写成“已实现中英术语映射和双语展示”之前，必须先做出可操作界面、术语表和样例输出；否则改为“面向双语扩展的风险识别系统”。
2. 当前 1716 帧处理结果主要证明 DeepSeek-VL2 图像描述与入库链路。若没有同批次 YOLO 检测记录，不应把 YOLO 的效果与这批验证数据合并表述。
3. “降低成本、提高效率、提升安全”必须给出基线、测量口径、公式和样本量，不能只写定性结论。
4. 东南亚适配不能只依赖标题。至少需要覆盖热带环境、弱网络、跨语言协作、本地术语和边缘部署中的两个真实约束。
5. 参考文献目前存在机构报告或规范名称过于笼统的问题。正式稿应补完整题名、年份、发布机构和可核验来源。

## 五、最高优先级补强项

### P0：提交前必须完成

- 将正式 PDF 从“学术论文初稿”改为“工业互联网数智应用解决方案说明书”。
- 增加四类创新点对照表：技术创新、模式创新、应用创新、价值创新。
- 增加实施路线、软硬件配置、部署拓扑、数据安全和故障恢复。
- 增加投入产出模型，至少提供保守/基准两种测算，并声明数据来源和假设。
- 使用真实数据补充处理耗时、单视频平均时长、帧处理吞吐、人工复核耗时和关键词抽检结果。
- 完成最小中英双语闭环：术语表、接口字段、前端切换或双语结果、人工审校状态。

### P1：显著增分

- 增加传统人工巡检、单一 YOLO、通用视觉大模型和本方案的对比矩阵。
- 选取 3 个端到端案例，展示原视频、关键帧、中文描述、英文描述、风险级别和复核结果。
- 增加系统边界图、业务流程图、数据流图、边缘-中心部署图和价值闭环图。
- 补充可复制交付包与商业模式：软件许可、项目实施、模型/术语库定制、年度运维服务。

### P2：有余力再做

- 增加泰语、老挝语或越南语中的一种术语样例，但不能用少量机器翻译样例冒充完整能力。
- 增加弱网缓存、断点续传或边缘推理演示。
- 对关键词抽取进行小规模标注评估，给出准确率、召回率和错误案例。

## 六、量化证据建议

| 指标 | 建议口径 | 当前状态 |
|---|---|---|
| 数据规模 | 视频数、总时长、抽帧数、场景类别数 | 已有视频数和抽帧数，缺总时长与类别分布 |
| 处理效率 | 总处理时间、帧/秒、单分钟视频处理时间、GPU 型号 | 缺失 |
| 描述质量 | 随机抽检 100 帧，人工评定正确/部分正确/错误 | 缺失 |
| 关键词质量 | 人工标注集上的 Precision、Recall、F1 | 缺失 |
| 双语质量 | 术语一致率、人工审校通过率、典型错误 | 未实现 |
| 人工节省 | 人工全量回看时间与系统筛查+复核时间对比 | 缺失 |
| 经济价值 | 年视频量、人工单价、算力与维护成本、回收期 | 缺失 |
| 安全价值 | 风险发现提前量、漏检下降或复核覆盖率 | 缺失 |

所有效果数字都应来自实测或明确标注为“测算值”，并附计算公式，避免将预测值写成既成成效。
